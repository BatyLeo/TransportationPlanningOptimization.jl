TransportationPlanningOptimization.AbstractArcCostFunction — Type
abstract type AbstractArcCostFunction

Abstract base type for cost functions defined on network arcs. Concrete subtypes determine how load/size on an arc is translated into cost.

Concrete subtypes must implement:

  • evaluate(arc_f::T, commodities; presorted=false) -> Float64: total arc cost for commodities.

Concrete subtypes may overload (sensible defaults are provided in terms of evaluate, see incremental_cost / lower_bound_incremental_cost):

  • incremental_cost(arc_f::T, existing::Vector{C}, new::Vector{C}) where {C<:LightCommodity} -> Float64: marginal cost of adding new to an arc that already holds existing. Defaults to evaluate(arc_f, existing ∪ new) - evaluate(arc_f, existing). Overload it when a closed form is cheaper (e.g. LinearArcCost, BinPackingArcCost).
  • lower_bound_incremental_cost(arc_f::T, existing::Vector{C}, new::Vector{C}) where {C<:LightCommodity} -> Float64: a relaxation of incremental_cost used by the lower-bound / filtering pass. Defaults to incremental_cost. Overload it only when the lower bound differs from the true cost and must under-estimate it (e.g. BinPackingArcCost, which relaxes the integer bin count to a fractional one). The typed Vector{C} signatures are needed to avoid method ambiguities with the generic fallbacks.
  • lower_bound_incremental_cost_with_order(arc_f::T, existing, order::Order) -> Float64: optional O(1) fast path over a whole order, using order.total_size or order.aggregate (see order_aggregate). Must return the same value as the commodity-vector method on order.commodities. Only the lower-bound passes call it. Defaults to the commodity-vector method, and existing may be nothing (empty arc). The MILP perturbations also use it as the linear relaxation of a custom cost, so keep it consistent with the true cost.
  • lower_bound_commodity_cost(arc_f::T, c::LightCommodity) -> Union{Float64,Nothing}: optional relaxed cost of the single commodity c, used to bound a FillThenSpillMode split of an order across the modes of a MultiModalArc. Defaults to nothing (no bound), see its docstring for the contract.

TransportationPlanningOptimization.AbstractModeSelector — Type
abstract type AbstractModeSelector

Abstract supertype for strategies that decide how a bundle's commodities are distributed across the modes of a MultiModalArc during greedy insertion. Concrete subtypes:

  • CheapestMode places each insertion entirely on the cheapest mode whose remaining capacity can absorb it.
  • FillThenSpillMode fills the cheapest mode up to its capacity, then spills overflow to the next-cheapest mode on the same edge.

New strategies are added as additional subtypes plus the matching methods on _edge_incremental_cost, _add_order_to_assignment!, _edge_lower_bound_cost and _direct_arc_order_lb_cost. The bound of FillThenSpillMode sums, over the commodities, the cheapest lower_bound_commodity_cost among the modes that can carry the commodity alone, which holds for any split. A mode without such a bound contributes 0 for the commodities it can carry.

TransportationPlanningOptimization.AbstractNodeCostFunction — Type
abstract type AbstractNodeCostFunction

Abstract type for per-node cost contributions. Mirrors AbstractArcCostFunction: node costs participate in path scoring exactly like arc costs, so they expose the same evaluate / incremental_cost / lower_bound_incremental_cost interface.

A node cost is charged once per incoming time-space arc, at that arc's head node, on the arc's full load (across modes for a multi-modal edge). The origin of a bundle's path is never charged, and a node reached through several incoming arcs is charged once per arc.

Concrete subtypes must implement:

  • evaluate(c::T, commodities) -> Float64: total node cost for commodities passing through the node. Must return 0.0 on an empty commodities vector (validated when the Instance is built, since a fresh or emptied edge assignment starts at node_cost = 0.0).

Concrete subtypes may overload (defaults are provided):

  • incremental_cost(c::T, existing, new) -> Float64: marginal cost of adding new to a node that already holds existing. Defaults to evaluate(c, existing ∪ new) - evaluate(c, existing). Overload it when a closed form is cheaper than two evaluate calls (and to avoid the vcat allocation).
  • lower_bound_incremental_cost(c::T, existing, new) -> Float64: a relaxation of incremental_cost used by the lower-bound / filtering pass. Defaults to incremental_cost. Overload it only when the lower bound differs from the true cost (it must under-estimate for the bound to stay valid).

The default NoNodeCost returns 0.0 for all of these.

TransportationPlanningOptimization.ArcFlowMILPPerturbation — Type
struct ArcFlowMILPPerturbation{F, O} <: AbstractPerturbation

Perturbation that reroutes several groups of bundles at once with an arc-flow MILP.

Groups of routed bundles (by default one per destination node) are drawn at random and their bundles are added in random order while the model stays within max_variables variables, until it is above 90% of it. The model has one binary variable per bundle and allowed TravelTimeGraph arc, flow conservation and elementarity constraints per bundle, and one integer bin variable per time-space edge with a bin cost. The load of the other bundles is kept fixed. The objective is the slope-scaled linear cost of the paths plus the bins of the shared edges, using the lower bound of each arc cost as its linear relaxation. The new paths are kept if the real cost increase is at most tolerance * cost(sol), otherwise the solution is left unchanged.

Multimodal arcs are not supported and raise an ArgumentError. The solver time limit is the smaller of the solver_time_limit field and the call budget left. The call budget is the time_limit keyword of perturbate!, minus the time already spent on the selection and the model build (the copy to the solver included). A call with less than MIN_MILP_TIME (1 second) left, before or after the build, changes nothing. HiGHS presolve can exceed the solver_time_limit field on large models, so with HiGHS the variable cap is what bounds the runtime.

Fields

  • group_by::Any = (b->begin …: function mapping a Bundle to its group key

  • optimizer::Any = HiGHS.Optimizer: JuMP optimizer (or optimizer factory) used to solve the MILP

  • max_variables::Int64 = 150000: maximum number of variables of the model (arc and bin variables)

  • solver_time_limit::Float64 = 180.0: time limit of the MILP solve in seconds

  • mip_gap::Float64 = 0.001: relative MIP gap at which the solve stops

  • tolerance::Float64 = 0.015: maximum accepted cost increase, as a fraction of the current cost

  • warm_start::Bool = false: whether the current routing is given to the solver as a starting solution (useful with a strong solver or small variable caps, off by default so time-limited solves still diversify)

TransportationPlanningOptimization.AttractReduceMILPPerturbation — Type
struct AttractReduceMILPPerturbation{O} <: AbstractPerturbation

Perturbation that pulls bundles onto a shared arc, or pushes them off it, and keeps the combination that pays with a MILP.

An arc of the TravelTimeGraph with a bin cost that carries at least one bundle is drawn at random. An arc that leaves more than min_candidate_ratio of the routed bundles with a new path is used at once, otherwise the priced arc with the most new paths is used. At most MAX_PRICED_ARCS (20) arcs are priced per call and the pricing stops at half of the effective time limit, including inside an arc. The effective time limit is the smaller of the solver_time_limit field and the call budget, which is the time_limit keyword of perturbate!. The solver gets what is left of the call budget after the pricing and the model build, at most the solver_time_limit field. A call with less than MIN_MILP_TIME (1 second) left, before the build or after it, changes nothing. Every bundle on the arc gets a "reduce" path, its cheapest elementary path that avoids the arc. Every other bundle that can use the arc gets an "attract" path, its cheapest elementary path forced through it. Paths respect the forbidden nodes and arcs of the bundle, and a bundle without such a path is not modeled. Without finite arc capacities, paths are priced against the current solution as it is, so the load of the bundle itself is counted in the costs. With finite capacities, the bundle is removed while its paths are priced. The arc is a TravelTimeGraph arc because bundles share it in relative time, the bins that decide the cost are on the time-space edges and are all in the model.

The model has one binary variable per bundle that chooses its current path (0) or its new path (1), and one integer bin variable per time-space edge with a bin cost that one of these paths uses. The load of the other bundles and reservations is kept fixed. The objective is the slope-scaled linear cost of the paths plus the bins of the edges, using the lower bound of each arc cost as its linear relaxation. The new paths are kept if the real cost increase is at most tolerance * cost(sol), otherwise the solution is left unchanged. The perturbation also changes nothing when no priced arc yields any new path.

Multimodal arcs are not supported and raise an ArgumentError.

Fields

  • optimizer::Any = HiGHS.Optimizer: JuMP optimizer (or optimizer factory) used to solve the MILP

  • solver_time_limit::Float64 = 180.0: time limit of the MILP solve in seconds, it also bounds the arc pricing

  • mip_gap::Float64 = 0.001: relative MIP gap at which the solve stops

  • tolerance::Float64 = 0.015: maximum accepted cost increase, as a fraction of the current cost

  • min_candidate_ratio::Float64 = 0.3: minimum fraction of the routed bundles that must get a new path for an arc to be chosen

  • warm_start::Bool = false: whether the current routing is given to the solver as a starting solution (off by default so time-limited solves still diversify)

TransportationPlanningOptimization.CheapestMode — Type
struct CheapestMode <: AbstractModeSelector

Mode-selection strategy that places the insertion entirely on the cheapest mode whose remaining capacity can absorb the load. Modes that would overflow are skipped. An edge whose every mode would overflow is treated as infeasible (Inf cost) during Dijkstra. The placement itself never throws on capacity: when a committed batch is not absorbed by any mode on top of its load (for example in the lower-bound passes), it goes to the cheapest mode that holds it alone (else the cheapest mode), which may overload that mode.

TransportationPlanningOptimization.FillThenSpillMode — Type
struct FillThenSpillMode <: AbstractModeSelector

Mode-selection strategy that fills the cheapest mode up to its capacity, then spills overflow to the next-cheapest mode on the same edge, and so on. Spilling only happens among the modes sharing the edge's transit time, since modes with distinct transit times live on separate edges. If the combined capacity across all modes on an edge is below the load, the edge is treated as infeasible (Inf cost) during Dijkstra. The placement itself never throws on capacity: when a committed batch does not fit on top of the load (for example in the lower-bound passes), it is re-split as if the modes were empty, with the remainder on the cheapest mode, which may overload the modes.

TransportationPlanningOptimization.GroupReinsertPerturbation — Type
struct GroupReinsertPerturbation{F} <: AbstractPerturbation

Perturbation that removes every bundle of one randomly chosen group and reinserts them one by one in random order along their cheapest paths for the current costs. The default groups bundles by destination node, so a whole destination is rerouted at once. For an origin grouping use group_by = b -> b.origin_id.

The new routing is kept if the cost increase is at most tolerance * cost(sol), otherwise the solution is left unchanged and the perturbation reports no change. The reinsertion of a group cannot be interrupted, so the time_limit keyword of perturbate! is accepted but ignored. The bundles are inserted with the mode_selector keyword of perturbate!. The group is rerouted many times per phase, so with verbose=true accepted calls are logged at info level and rejected calls at debug level.

  • group_by::Any = (b->begin …: function mapping a Bundle to its group key

  • tolerance::Float64 = 0.015: maximum accepted cost increase, as a fraction of the current cost

  • allow_multimodal (default: false): opt-in switch for multi-modal legs. When false,

duplicate (origin_id, destination_id) arcs raise an ArgumentError. When true, duplicates are auto-promoted to a MultiModalArc.

Discretization and Normalization

  1. Start Date: The time horizon starts at midnight of the earliest release date

(for departure-based) or the earliest possible start (for arrival-based).

  1. Time Steps: Dates and periods are converted to discrete steps using period_steps.
  2. Consolidation: Commodities with the same origin, destination, and delivery step are

grouped into Orders. Orders with the same origin and destination are grouped into Bundles for routing.

  1. Graphs: Both TimeSpaceGraph and TravelTimeGraph are constructed.

The input is kept as given in instance.input, and each input commodity is mapped to its bundle and order in instance.commodity_to_order.

Commodities with their origin equal to their destination are dropped: they never move and cost nothing, so they are mapped to (0, 0) in instance.commodity_to_order, get an empty route in a Solution and are ignored by the time grid. Arcs from a node to itself are ignored with a warning. The role of each node is derived from the commodities and arcs, and the nodes that are both commodity endpoints and crossing points are split internally into a hub and endpoint copies. Arcs that could only be used to cross a transit=false node are ignored with a warning (see Node). An ArgumentError is thrown if every commodity is dropped, or if a commodity endpoint is not a node id of nodes, or if a forbidden node or arc endpoint is not a node id of nodes.

TransportationPlanningOptimization.SolutionState — Method
SolutionState(
    solution::Solution,
    instance::Instance{<:Bundle{<:Order{IDA, I}}}
) where {IDA, I}

Build the SolutionState of the plan solution on instance, the reverse of Solution(solution_state, instance). The routes are the source of truth and give the paths and the input arcs (modes) of every commodity. The arc_flows are ignored, and the capacity reserved for commodities dropped by an extraction is not rebuilt. A leg on an input arc with no arc in the instance (a loop, a skipped transit=false arc or an arc dropped by an extraction) is rejected. Commodities not routed by the instance (mapped to (0, 0), such as the ones with their origin equal to their destination) must have an empty route. Every slot of every edge is repacked by first-fit decreasing, so bins and costs only equal those of the original state for linear costs (up to floating point summation order). Capacity is not checked, run is_feasible on the result. Several legs on the same arc at the same position are merged, and the solution-level round trip Solution(SolutionState(solution, instance), instance) == solution only holds for solutions produced by Solution(solution_state, instance). Other plans come back normalized, with the legs of one leg position merged and in slot order and identical copies attributed by count.

An ArgumentError is thrown for the first rule a route breaks, checked in this order:

  • a wrong number of routes, a route for a dropped commodity or an empty route for a kept one,
  • an arc index out of range or absent from instance, a non-positive quantity or a leg quantity above the commodity quantity, a commodity size above the bin capacity of the arc, dates off the time grid or a transit time different from the arc one,
  • copies not adding up to the commodity quantity (also when they are split across legs between two nodes that differ in dates or are not consecutive),
  • a route that does not start at the commodity origin (a hub of an endpoint copy counts as the origin, and likewise for the destination), legs that are not connected (also a route crossing a transit=false node), wait anywhere but before the first leg (arrival-date instances) or after the last leg (departure-date instances), or overlap,
  • a route that does not end at the commodity destination,
  • a route not pinned to the order date, which is its arrival in arrival-date mode and its departure in departure-date mode,
  • a route longer than the maximum delivery time of its commodity group,
  • a route that leaves the time horizon of the instance when wrap_time is off (defensively, also a node that routes cannot cross at that date),
  • a route through a forbidden node or arc, or not elementary,
  • commodities of one group (same origin, destination and group key) that do not follow the same path (same nodes and transit times) at the same offsets from their order date.

TransportationPlanningOptimization.iterated_local_search! — Method
iterated_local_search!(
    sol::SolutionState,
    instance::Instance,
    perturbations::Vector{<:AbstractPerturbation};
    config::ILSConfig,
    cost_update!::Union{Nothing, Function},
    on_improvement::Union{Nothing, Function},
    mode_selector::AbstractModeSelector,
    rng::Random.AbstractRNG,
    verbose::Bool
) -> ILSResult

Run Iterated Local Search on sol.

Cycles through perturbations round-robin, after dropping the ones for which supports_instance returns false (logged once when verbose, an ArgumentError is thrown when none is left). Each round repeats the perturbation until the accumulated number of changed bundles reaches the change threshold, or the accumulated cost increase reaches the cost threshold, or the perturbation time limit is hit. Each perturbation call receives the time it may use, the smaller of the time left in the main loop and in the perturbation phase. No call starts with less than MIN_CALL_TIME (1 second) left, or half of the shorter of the perturbation limit and the main loop limit when that limit is under 2 seconds. The accumulators are only reset after a local search phase. A round with no accumulated change counts toward max_no_change. After each perturbation phase, a solution cheaper than the best becomes the new best, so an improvement is never lost when the change threshold is not reached. Local search runs only once the change threshold is reached, followed by a second local search if the result is within 0.025% of the best cost. A result better than the best (including a best set by a perturbation phase) becomes the new best. max_no_improv counts the local search phases with no new best since the previous one, including the perturbation phases that came before it. config.time_limit is the wall-clock limit of the whole call. The main loop, with its phases, stops config.final_ls_time_limit before it. config.ls_time_limit only limits each local search phase inside the loop. At the end the best solution is restored and polished by a final local search of at most config.final_ls_time_limit, and of at most the time left in config.time_limit. It does not run when no time is left.

mode_selector is used by every local search and passed to every perturbate! call, so it must be the one the solution was built with.

The optional cost_update! callback is called once before the loop, then after every local search phase. It receives (instance, sol) and may mutate instance.travel_time_graph.cost_scaling or other mutable state. Slope scaling is one implementation: it only shapes the MILP perturbation objectives. The cost scaling factors of the travel time graph are always emptied when the call returns, also when it throws, including factors set by the caller.

The optional on_improvement callback is called each time a new best solution is found. It receives (sol, best_cost, elapsed_seconds).
